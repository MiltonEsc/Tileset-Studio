# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**Tileset Studio** — a React + Vite web app to author 47+1 autotile tilesets (pixel art at 8 / 16 / 32 / 64 px, or **non-pixel "smooth" cartoon/anime** at 128 / 256 px — see Smooth tilesets) and design/test levels with them. **Two top-level views** (header tabs `Editor` / `Levels`, `activeView`):

- **Editor** — the left workspace switches between **Tileset / Assets** (`editorKind`):
  - *Tileset*: create the 48-tile sheet three ways — draw a base tile, generate procedurally from a biome palette, or generate a base tile with the OpenAI Images API. Preview all 48 tiles and export an 8×6 PNG. **Click any tile in the sheet/preview to hand-edit it** (a per-tile override baked over the generated sheet; overrides persist in saved definitions and are marked with an accent corner dot). Procedural tilesets can be **animated** (2–4 seeded shimmer frames — see Animated tiles below).
  - *Assets*: author **scenery props** (trees, houses, barrels…), multi-cell (1×1 to 4×4) with a **transparent background**. Generate with the OpenAI Images API and/or draw by hand, save to a gallery, export each prop or an atlas PNG. (Rendered by `AssetsView`.)
- **Levels** — paint or procedurally generate a level grid that is **autotiled live** with the active tileset (the "test bench"). Cursor-centered zoom via **`@use-gesture/react`** (mouse/trackpad wheel + touch/trackpad **pinch**), bound on `LevelCanvas`'s wrapper with `eventOptions:{passive:false}` and `touchAction:'none'`; the zoom math is `zoomToCell` (sets `zoomAnchor`, restored by a `useLayoutEffect` on `cellPx`). Collapsible side panel, "Fit" button. A **Terrain/Props/Select tool toggle**: Terrain paints; Props places saved props (pick one in the Tools section's prop grid, left-click to place, right-click to remove; a ghost previews placement); **Select** edits placed props — click to select (dashed accent highlight), drag to move (one undo entry per drag), Flip/Rotate/Reset, Forward/Backward z-order (array order = draw order, mirrored to pixi via `zIndex`), Delete key or button removes.

**UI convention: no emojis** — labels/buttons use plain text. Don't add emoji to the interface.

## Commands

```bash
npm install        # install deps
npm run dev        # dev server (Vite) — required for the OpenAI proxy + reads .env.local
npm run build      # production build to dist/
npm run preview    # preview the production build
```

`.env.local` (git-ignored) provides the AI keys — `VITE_GEMINI_API_KEY`, `VITE_OPENAI_API_KEY`, `VITE_FAL_API_KEY` (fal.ai/FLUX), `VITE_CLOUDFLARE_API_TOKEN` + `VITE_CLOUDFLARE_ACCOUNT_ID` (Cloudflare Workers AI / SDXL — needs **both**) and/or `VITE_RECRAFT_API_KEY` (Recraft V3); the active model's provider decides which is used — plus `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` (persistence). Keys are **read from env only — there is no API-key field in the UI** (it was removed; ⚠️ `VITE_*` vars are still bundled into the client at build time, so this hides the key from the UI but isn't true secrecy — proxy through a backend for that). Without the Supabase vars, the gallery hooks load empty and set an `error`. DB schema lives in `supabase/migrations/` (see Persistence).

The pure core logic has a small **`node --test`** suite — `npm test` runs `src/core/*.test.js` (bitmask/export/generator/idea/variant coverage). There is no linter and no UI/hook test runner; verify UI changes by running `npm run dev` and exercising the app (Playwright is a devDependency and is used for manual smoke tests; see git history of how it was driven).

## The 48-tile system (the core abstraction)

Everything keys off an **8-bit neighbor bitmask** with a diagonal-pruning rule: a diagonal bit only counts when **both** of its adjacent cardinal neighbors are present. This collapses 256 raw values to exactly **47 valid configurations + 1 empty slot = 48**, laid out as an **8×6** sheet.

- [src/constants/bitmaskTable.js](src/constants/bitmaskTable.js) is the single source of truth. It builds `BITMASK_TO_INDEX`, `INDEX_TO_BITMASK`, and `INDEX_TO_CATEGORY` at module load and asserts exactly 47 valid masks. `BITS` defines the bit for each direction (TL/T/TR/L/R/BL/B/BR).
- **Sheet index 0 is the empty tile**; indices 1..47 are the autotile configs (in ascending bitmask order). A tile array is always `ImageData[48]`.
- Any code that maps neighbors → tile must use the same pruning rule, or masks won't match the table. See [src/core/autotile.js](src/core/autotile.js) `getTileIndex`.

## Architecture

State lives in per-area hooks; `App.jsx` holds only the cross-cutting UI state (`activeView` = `'editor' | 'level'`, `editorKind` = `'tileset' | 'prop'`, `tileSize`, `mode`, `levelMode`, the active editor tileset descriptor `editorTileset` + its source `editorSourceDef`, `levelTool`/`terrainTool`/brush size, `propTransform`, level zoom/sidebar state) and wires panels together. No Context, no external state lib — the tree is shallow, props are passed directly. The `assets`/`tilesets`/`levels` gallery hooks are instantiated in `App.jsx` and shared across views — e.g. `assets` feeds both the Assets editor and the Level Designer's prop placement. Loading a saved tileset/level routes through `App.jsx#applyTilesetDefinition`, which regenerates the 48 tiles.

**View switching is keep-alive (perf).** The three workspaces (EditorWorkspace/tileset, AssetsView, LevelsWorkspace) are **mounted once and toggled with CSS** (`display: contents`/`none` wrapper) instead of unmount/remount, so switching back is instant — no lazy re-download, no pixi re-init. AssetsView/LevelsWorkspace still load lazily (latch refs `everAssets`/`everLevel` mount them on first activation); App prefetches both chunks (incl. pixi) on `requestIdleCallback` so even the first switch is fast. Because a hidden view stays mounted, each kept-alive view takes an **`active` prop** to pause its background work while off-screen: `LevelCanvas` stops `app.ticker` + its animation `setInterval`; `LevelsWorkspace`/`AssetsView` skip their global `keydown` (Ctrl+Z) listeners (else they'd hijack the visible editor); `EditorWorkspace`'s `SheetCanvas` stops its frame-cycle interval. **When adding a global listener or interval to any workspace, gate it on `active`.**

**Per-layer tilesets in the level view**: each level layer carries an optional `tileset` (`{name, tileSize, definition, savedId?}`); `null` means "use the current editor tileset". `App.jsx`'s `layerTiles` memo resolves every layer to actual `ImageData[48]` (cached in a `WeakMap` keyed by the `layer.tileset` object reference — tiles are expensive to regenerate and the reference is stable across paint flushes). When the level view is active, `GalleryDock`'s `onSelectBiome` / `onLoadTileset` assign the picked tileset to the **active layer** via `level.setLayerProp` instead of replacing the editor tileset; saved tilesets whose `tile_size` ≠ the level tile size are rejected with a transient notice.

### "Pixel Workbench" design system
The whole UI uses a single locked **pixel** theme (ported from a standalone mockup): hard corners (`--bw: 2px`, small `--r-*`), offset block shadows (`2px 2px 0`), a 4px background grid, bundled fonts ([src/assets/fonts/](src/assets/fonts/): Albert Sans = `--ui`, JetBrains Mono = `--mono`, Silkscreen = `--pixel` for section eyebrows/brand), and a teal accent `#2fd6a6`. There is **no theme switcher** — pixel is the only direction.

- **Reusable UI primitives** live in [src/components/ui/](src/components/ui/): `PixIcon` (+ `icons.js` string-grid icons), `Btn` (variants primary/accentSoft/solid/ghost/outline/danger), `Segmented`, `Section` (collapsible, pixel eyebrow), `ColorRow`. These render with inline styles bound to the CSS tokens — prefer them over hand-rolled controls.
- **Layout** (mockup classes in [src/App.css](src/App.css)): `.topbar` (brand + `Segmented[Editor|Levels]` + `Segmented[8|16|32|64]`), `.editor-grid` (3 cols `286px 1fr 308px` of `.panel`s), `.library` footer (the GalleryDock), `.stage` center, `.map-scroll`/`.map-canvas` for the manual painter.
- Each view is a **workspace component**: `Editor/EditorWorkspace.jsx` (tileset), `Assets/AssetsView.jsx` (props), `Level/LevelsWorkspace.jsx` (levels). `App.jsx` only holds state/handlers and picks the workspace.

**Core (pure logic, no React):** [src/core/](src/core/)
- `tileGenerator.js` — draw mode: clones the base `ImageData` and applies borders per bitmask → `ImageData[48]`. Borders are applied in a **single pass** (`applyBorders`) so corner pixels aren't darkened multiple times; exposed edges are always **darkened** (corners a bit more than straight edges).
- `proceduralGen.js` — procedural mode. `generateAllBiomeTiles(biome, tileSize, frameSeed = 0)` paints each tile from a biome palette: primary fill + a light Bayer dither grain + a **distinctive per-biome texture** (`applyBiomePattern(params.patternFn, …)` → `grass`/`sand`/`snow`/`stone`/`water`/`cracked`/`brick`/`dirt`/`mud`/`ash`/`moss`/`swamp`/`cobble` (the last is a seamless toroidal-Voronoi cobblestone: rounded stones + mortar + rim shading, used by the Piedra/Musgo ground templates), each using the full 5-colour palette — highlight/secondary/shadow — for depth), then **textured borders** (`paintEdge` — irregular inner boundary + scattered border/shadow/highlight pixels, NOT a flat color bar) + inner-corner highlights. ⚠️ The pattern and the dither **both** apply now; previously the pattern was an `else` to `dither`, so every dither:true biome rendered as flat dither and they all looked the same. The 8 default biomes ([constants/biomes.js](src/constants/biomes.js)) each pick a fitting `patternFn` + tuned palette; saved procedural tilesets store only `{biomeId, colors}` and pull `proceduralParams` from `BIOME_MAP`, so editing a biome's pattern/palette re-skins existing saves. The same file also exports **`GROUND_TEMPLATES`** — a curated "Terreno" category (Césped/Tierra/Arena/Nieve/Barro/Piedra/Lava/Ceniza/Musgo/Pantano, ids `g-*`), each a biome-shaped `{patternFn, palette}` so it generates instantly (AI textures can re-skin on top). `BIOME_MAP` covers **both** arrays so any id regenerates. The gallery ([GalleryDock.jsx](src/components/BiomeGallery/GalleryDock.jsx)) surfaces them under a **"Terreno" filter chip** as `GroundCard`s, which (unlike biome `PaletteThumb`s) render the **real procedural texture** via `SavedTileThumb` so you see the form. `frameSeed > 0` produces an **animation frame**: edges re-scatter with a shifted seed + a light interior shimmer (frame 0 = the exact static sheet); the memo cache keys include the frame seed. Also `generateTilesFromTextures(centerData, edgeData, tileSize)` — composes all 48 tiles from a **center texture + edge source**. `edgeData` = an AI/ImageData texture (e.g. snow) → copied as a **beveled** strip (`paintEdgeFromTexture` → `copyPixelShaded`); or null → the border is **synthesized from the center material's own average colour, darkened in-hue** (`darkenKeepHue` keeps the hue + boosts chroma so it stays the same colour just deeper — NOT near-black, NOT the old palette speckle which gave e.g. a lava center grass-green borders) into a **3-tone depth bevel** (`paintEdgeBevel`: outer rim = shadow, body = border, inner lip = highlight). Border depth is **uniform** (`= ew` on every column, no random jitter) so a run of border tiles has **constant width and no doubled pixels at the junction** (tiles seamlessly along the run; verified by a test that the top-edge tile's left column == right column). Using the *average* (not the center's boundary rows) keeps the border uniform on all four sides (AI edge rows carry bands/artifacts). **Inner (concave) corners** are a **defined notch** (`paintInnerCornerTones`/`paintInnerCornerTexture`: a short shadow notch down both meeting edges + a border diagonal + a highlight tip, scaled by `ew`) instead of the old single pixel. It composes (never crops an AI sheet) so autotiling is always correct. Used by AI procedural generation (below); `handleAIProcedural` also infers the palette swatches from the AI center.
- `tilesetDefinition.js` — `tilesFromDefinition(def, tileSize)` — shared utility that regenerates `ImageData[48]` from a saved tileset definition (`{mode:'draw',basePixels}`, `{mode:'textures',centerPixels,edgePixels,colors}`, or procedural/biome). Also owns **per-tile overrides** (`applyTileOverrides(tiles, {idx: Uint8ClampedArray}, tileSize)` copy-on-write replace; `decodeDefinitionOverrides` reads a definition's `overrides: {idx: base64}`; `tilesFromDefinition` applies them automatically) and **animated tiles** (`framesFromDefinition(def, tileSize)` → the N-1 extra seeded frame sheets for procedural defs with `animationFrames: N`, overrides kept static per frame; `ANIM_FRAME_MS`/`MAX_ANIM_FRAMES` shared by the live view, editor preview and Tiled export).
- `autotile.js` — level grid (`Uint8Array`, 1=solid/0=empty) → per-cell sheet index (`computeIndexMap`).
- `levelGenerator.js` — `GENERATORS` map: caves (cellular automata), islands (value noise), platforms, rooms (dungeon), random. Seedable via mulberry32 (`randomSeed()` exported). Each generator's tunable params are described by **`GENERATOR_PARAMS`** (per-generator `{key,label,min,max,step,default}[]`), with `defaultParams(type)` and `sanitizeParams(type, params)` (clamps to range, fills missing, drops unknown keys, enforces min≤max pairs). The UI ([Level/GeneratePanel.jsx](src/components/Level/GeneratePanel.jsx)) builds sliders from this metadata and passes the params through `useLevelMap.generate(type, opts)` (which already accepted opts) — the generator algorithms are untouched. It also has a seed field (reroll/lock) and a **Variations** strip (6 seeds → `GridThumb` previews, click applies). A sibling collapsed **"AI ideas"** section lazily mounts [Level/LevelIdeaPanel.jsx](src/components/Level/LevelIdeaPanel.jsx): describe a theme → `aiText.generateText` → `levelIdeas.parseIdeas` → cards (each carries `{generator, params, seed}` and a `GridThumb` preview); clicking a card calls `level.generate(...)`. `useAIModel(models, storageKey)` is now generalized (defaults to image `AI_MODELS`; the idea panel passes `TEXT_MODELS`).
- `exportSheet.js` — composites `ImageData[48]` into an 8×6 PNG (optional `scale` for 1×/2×/4×) and triggers download. Optional `frames` stack below the base sheet as full 8×6 blocks (animated tilesets → one tall PNG).
- `exportLevel.js` — exports a level to **game-engine formats**. `buildLevelModel` resolves every visible layer to a flat tile-index array (-1 = empty) via `computeIndexMap` + manual overrides, dedupes tilesets by `layerTiles` reference and renders each with `composeNativeSheet`. `exportLevelTiled` → native `.tmj` (Tiled JSON: gid 0 = empty, `firstgid + index` otherwise, props as an objectgroup). `exportLevelGodot` / `exportLevelUnity` → a generic `.json` (flat per-layer `data`, tileset refs) plus a ready-to-use importer script (`level_importer.gd` using `TileMapLayer.set_cell`; `LevelImporter.cs` using `Tilemap.SetTile` with Y-flip) — high-level engine APIs, no fragile binary scene files. The tileset PNG(s) download alongside (spaced-out multi-download). Prop *placement* is exported; prop images are not. **Animated tilesets**: frame blocks (48 tiles each) append to the sheet after the variants at `frameStart`; the Tiled entry gets `tiles[].animation` for every autotile id (cycling id → frame copies), and the generic JSON carries `animation: {frameCount, frameStart, frameDuration}` (the bundled Godot/Unity importers place the static frame and ignore it).
- `composeSheet.js` — `composeNativeSheet(tiles, tileSize)` blits `ImageData[48]` into one offscreen 8×6 `<canvas>` so the level editors/minimap/tile-picker can `drawImage` individual tiles fast.
- `tileVariants.js` — **anti-repetition** for the fill tile (`FILL_INDEX` = `BITMASK_TO_INDEX.get(0xFF)`, = 47). `makeFillVariants(fillTile, size)` derives 3 variants by **mirroring the interior** (flipX/flipY/rot180; border row/col untouched → seamless preserved, palette preserved, deterministic — a clearly visible change); `pickVariant(x, y, total)` is a per-cell hash. Gated by the **"Tile variation"** toggle (level Options). Used in three consistent places (same hash ⇒ same variant per cell everywhere): `LevelCanvas` (live render — variant textures in `getTerrainTextures`, fill cells swap texture; toggling forces a rebuild via `state.variation`); `LevelsWorkspace.exportLevelPNG` (bakes variants into the PNG); and `exportLevel.buildLevelModel` (`tileVariation` flag → appends variant tiles to the sheet at indices 48.., extends `rows`/`tileCount`, and rewrites fill cells to the variant tile index — so Tiled/Godot/Unity exports get the variety too, driven by `tileCount`/`columns`).
- `aiTile.js` — multi-provider (Gemini / OpenAI / fal / Cloudflare / Recraft) image call + downscale to a base **terrain tile** (opaque, see below). Owns `AI_MODELS`, `providerForModel`, `resolveApiKey`, `generateImage`. **Color quantization uses [image-q](https://www.npmjs.com/package/image-q)** (`quantizePixels` → Wu palette + optional dithering via `applyPaletteSync`), replacing the old hand-rolled median cut. `postprocessTilePixels`/`generateBaseTileWithAI` take a `dither` option (`DITHER_OPTIONS`: Off / Floyd–Steinberg / Atkinson, surfaced in the tile + procedural AI panels). image-q is a static import here but rides the **lazy AI chunk** (this module is only reached via lazy panels) so it stays out of the initial bundle.
- `aiAsset.js` — same `generateImage` dispatcher for **scenery props**: magenta background + chroma-key + non-square downscale (see below). Re-exports `AI_MODELS` from `aiTile.js`.
- `aiText.js` — **text** generation (chat/completion), reusing `aiTile.js`'s `resolveApiKey` + dev proxies (`GEMINI_BASE`/`OPENAI_BASE` are now exported). `TEXT_MODELS` (`gemini-2.5-flash`, `gpt-4o-mini`) + `generateText({prompt, system, model})`; both providers asked for JSON. Same `.env.local` keys as the image path.
- `levelIdeas.js` — the level "idea cards" assistant core (pure/tested): `buildIdeaSystemPrompt()` (derived from `GENERATOR_PARAMS` so it can't drift), `buildIdeaUserPrompt(theme)`, and `parseIdeas(raw)` which turns the model's JSON into a **safe** concept list — drops unknown generators, `sanitizeParams` each, fills/clamps seeds, caps at 6. The model only proposes `{generator, params}`; the app generates the grid, so output is always valid.
- `exportAsset.js` — exports a prop as a transparent PNG (`exportAsset`) or all props as a grid atlas (`exportAllAssets`).
- `exportRaw.js` — saves/previews the **raw image an AI returned** before the tile pipeline: `rgbaToDataURL` (thumbnail), `downloadRgbaPng` (full-res PNG download), `parseRawSize`. Consumed by `RawAIPreview`.
- `imageImport.js` — `fileToRgba(file)` decodes a user-imported image File into a native-size RGBA buffer (for `processImageToTile` → procedural composition).
- `canvasUtils.js` — shared pixel ops: `floodFill`, `darkenRegion`, dither, `drawLineInto`, `drawRectInto`, `paintBrush`, hex/RGBA helpers. **These already take `width`/`height` separately**, so they work for non-square asset canvases too.

**Hooks:** [src/hooks/](src/hooks/)
- `useDrawingCanvas.js` — square tile pixel buffer (`Uint8ClampedArray` at native tile resolution), tools (pencil/eraser/fill/line/rect/rectFill/eyedropper), brush size, zoom, undo/redo, shape tools with a live `preview` overlay, `loadPixels` (used by AI), plus `clear()` for the sidebar reset action. Eraser paints gray. Zoom is CSS-only; pixel data is never scaled.
- `useAssetEditor.js` — like `useDrawingCanvas` but for **non-square, transparent** prop canvases: takes `(width, height)`, default buffer is fully transparent (alpha 0), and the **eraser writes alpha 0** (real transparency). Same tools/undo/redo, plus `applySolidify` + a `rawRef` source buffer for the Edge-solidity control (see AI props below).
- `useTilesheet.js` — holds `ImageData[48]`; `generateFromBitmap` / `generateFromBiome`.
- `useLevelMap.js` — level grid state: paint, generate, clear, fill, resize. Also owns **`placedProps`** (`{ id, assetId, x, y, flipX?, flipY?, rotation? }[]`, x/y = anchor cell) with `addProp(assetId,x,y,transform?)` / `removeProp` / `clearProps`. **Prop transforms** (B3): `addProp` takes an optional `{flipX,flipY,rotation}` and stores only non-default fields (back-compatible). App holds the active `propTransform` (the placement transform); the props tool has a Flip H / Flip V / Rotate / Reset row and the placement ghost previews it. `LevelCanvas` renders transforms via `applyPropTransform` (centered anchor + signed scale for flip + `rotation`). Persistence is free (props ride in the `placed_props` jsonb); export carries them: Tiled object `rotation` + `flipX/flipY` in `properties`, generic JSON gets all three. Placed props are edited via the **Select tool**: `updateProp(id, patch, recordHistory)` (move/transform; `recordHistory:false` lets a drag be one undo entry — the canvas pushes on the first cell change only) and `movePropZ(id, dir)` (swaps array order = draw order). Hit-testing (which prop covers a cell) is `App.jsx#findPropAt` — rotation-aware (90°/270° swap the visual extents around the footprint centre), shared by right-click remove and Select. **Global undo/redo**: a snapshot history (`undo`/`redo`/`canUndo`/`canRedo`) covers all committed level state — every layer's terrain grid + manual tiles, props, layer add/remove/move, and resize. Snapshots store *references* to the already-immutable committed state (no deep clone); a drag is one entry (captured at stroke start, pushed on first real change via `noteStrokeChange`), one-shot ops push before mutating, and `loadState` resets the stacks. `restore` strips each layer's `_dirtyTerrain`/`_dirtyManual` hints so `LevelCanvas` re-diffs whole grids (the hints describe the original edit, not the diff from what's on screen). Wired in `LevelsWorkspace` (Undo/Redo buttons + Ctrl+Z / Ctrl+Y, ignored while typing). Layer rename/visibility are intentionally not tracked. **Layers**: `layers` is `{id, name, kind: 'autotile'|'manual', visible, tileset, grid, manualTiles}[]` with add/remove/move/rename; `resize` re-copies every layer and drops placed props whose anchor falls outside the new bounds. Paint strokes are **RAF-batched** (a mutable stroke buffer flushes to React state at most once per frame, with `_dirtyTerrain`/`_dirtyManual` cell hints for incremental canvas updates).
- `useAssets.js` / `useTilesets.js` / `useLevels.js` — gallery hooks backed by **Supabase** (see Persistence below). Each loads its table on mount (async) and exposes **`loading` + `error`**, which the consumers now render (GalleryDock rail banner, AssetGallery, the level Save/load section) so a Supabase failure is visible instead of a silently empty gallery. `remove` is **optimistic with rollback**: it captures the row (via a list ref) before removing and re-inserts it at its original index if the server delete throws, so the UI never claims something is gone while it still exists in the DB. `add/save` call `src/lib/db.js` then update local state. Pixel buffers / grids are base64 via `src/lib/serialize.js`. No localStorage.
- `useBiomeGallery.js` exists but is **not currently wired** — App manages the active biome via `editorTileset`/`editorSourceDef` directly.

The pure resize helpers live in **[imageResize.js](src/core/imageResize.js)** (extracted from `aiTile.js`) so `tilesetDefinition` can use them **without dragging image-q into the main bundle**.

Rendering resolves each layer's sheet from `layerTiles` (see "Per-layer tilesets" above): `LevelsWorkspace` receives the pre-resolved `{tiles, tileSize}[]` from `App.jsx` and feeds it to `LevelCanvas`, the manual palette, the layer thumbnails and both exports.
- `Assets/` — AssetsView (re-skinned), AssetCanvas, AssetAIPanel, SizeSelector, AssetGallery.

**Data layer:** [src/lib/](src/lib/) — `supabase.js` (**`getSupabase()`** lazily dynamic-imports `@supabase/supabase-js` + creates the client on first use, so the heavy SDK is a separate chunk out of the initial bundle; returns `null` when unconfigured, else a memoized `Promise<client>`), `db.js` (async CRUD per table — each fn does `const sb = await getSupabase()`), `serialize.js` (base64 codec). See Persistence below.

## Conventions

- **Canvas rendering**: native logical resolution on the `<canvas>` (`width=tileSize`), scaled up with CSS + `image-rendering: pixelated`. Grid overlays are a separate absolutely-positioned canvas with `pointer-events: none`. Mouse → cell: divide client offset by the on-screen cell size and floor.
- **Tiles are `ImageData`** throughout; to blit fast, pre-render each tile to a small offscreen `<canvas>` and `drawImage` (see `LevelCanvas`), rather than `putImageData` per cell.
- **Tile size is global (8/16/32/64/128/256, default 32)** and everything keys off it; the header `GRID` selector and a "Tile size (paint px)" Segmented in the Levels **Tileset** section both drive it via `handleTileSizeChange`. A startup **`ProjectModal`** ([ui/ProjectModal.jsx](src/components/ui/ProjectModal.jsx)) picks the initial grid + a `projectName` (the header `project-new-btn` reopens it); the GRID selector stays free to change it later. ⚠️ Regenerating 48 tiles at **128/256 px** is heavy (~12 MB + GPU upload) and would freeze the click — `handleTileSizeChange` factors the work into `regenForSize(size)` and, for `≥128`, sets a `regenerating` flag (a `.regen-overlay`) and runs it after a double-`requestAnimationFrame` so the UI paints the "Regenerating…" state instead of freezing. In the Levels view, applying a **saved tileset** whose `tile_size` ≠ the level tile size is **blocked with a transient notice** (`showLevelNotice` → a `.level-status-notice` pill); biomes are procedural so they regenerate at the level size and always match. Anything that displays tiles must scale to it, not assume 16: the tilesheet preview grid uses `repeat(8, 1fr)` + `aspect-ratio` (fits any size), editor/preview zooms are computed from the tile size (`useDrawingCanvas` default, `ZoomControl` bounds, `TileCell`/`TilePreviewMosaic`/`BiomeCardPreview`), and border width scales as `max(2, round(tileSize/8))` in `tileGenerator`/`proceduralGen` so it stays visible at 64px. When adding tile-displaying UI, derive sizes from `tileSize`.
- **Styling**: one global [src/App.css](src/App.css) with CSS custom properties (`--bg`, `--accent`, etc.). Class-based, no CSS modules. Dark theme with a more modern generator-like left sidebar and glassy workspace panels.
- Code and comments are in English; the app author communicates in Spanish.

## AI base-tile generation (Gemini + OpenAI + fal + Cloudflare + Recraft)

[src/core/aiTile.js](src/core/aiTile.js) + [AITilePanel.jsx](src/components/Generator/AITilePanel.jsx) generate a base tile from a text prompt. **Five providers, picked per model** via `providerForModel(modelId)`:

- `AI_MODELS` (aiTile.js) tags each model with a `provider`: **Gemini** (`gemini-2.5-flash-image` default, `gemini-3-pro-image`), **OpenAI** (`gpt-image-1`, `gpt-image-1-mini`), **fal** (`fal-ai/flux/schnell`, `fal-ai/flux/dev` — FLUX), **cloudflare** (`@cf/stabilityai/stable-diffusion-xl-base-1.0` — SDXL via Workers AI, generous free tier) and **recraft** (`recraftv3`). `generateImage({prompt, model, quality, outputFormat})` resolves the provider, gets the matching key from env, and dispatches.
- **Gemini request** (`buildImageRequestBody`): endpoint **`v1beta`** `:generateContent`, header `x-goog-api-key`. `generationConfig` uses `responseModalities: ['IMAGE']` + **`imageConfig: { aspectRatio }`**. ⚠️ Do **not** use `responseFormat` or the `v1` endpoint — both make the API reject the body with *"Unknown name responseFormat / responseModalities at generation_config"* (the original bug). Image bytes come back as `candidates[].content.parts[].inlineData.data` (base64).
- **OpenAI request** (`requestOpenAIImage`): endpoint `v1/images/generations`, header `Authorization: Bearer`, body `{model, prompt, n, size:'1024x1024', quality}`. Returns `data[0].b64_json`. Don't send `response_format` (retired).
- **fal request** (`requestFalImage` / `buildFalRequestBody`): endpoint `${FAL_BASE}/<model>` (e.g. `fal.run/fal-ai/flux/schnell`), header `Authorization: Key`, body `{prompt, image_size:'square_hd', num_images:1, sync_mode:true, enable_safety_checker:true, output_format}`. **`sync_mode:true` makes fal return the image inline as a data-URI** (in `images[0].url`) instead of a CDN URL, so there's no polling or cross-origin canvas tainting — `runFalAttempt` passes that url straight to `decodeGeneratedImage`. Defaults to PNG (`output_format`); FLUX `schnell` keeps its own 4-step default (no `num_inference_steps` pinned). ⚠️ FLUX needs special handling on the TILE path: it ignores instruction-style prompts and **inverts negations** ("avoid drawing a border" → draws a border) — see the `CAPTION_PROVIDERS` prompt note above (the caption now asks for flat 2D pixel-art terrain, not a realistic material map). FLUX also biases toward centered/vignetted compositions, so `generateBaseTileWithAI` center-crops diffusion images before downscaling with an **adaptive fraction** (`pickFalCropFraction`): it scales with **tile size** (smaller tiles crop tighter so detail stays legible — `TILE_CROP_BASE` 0.30/0.40/0.55/0.72 for 8/16/32/64) and tightens further (×0.7) when `vignetteScore` says the image is a centered blob. Props are NOT cropped (a centered subject is desired there). The downscale itself (`postprocessTilePixels`) is **size-adaptive**: a progressive mip-halving downscale (`downscaleRgba`) cleaner than one giant box average, plus a color budget (`tileColorBudget` 8/12/16/20) and unsharp amount (`tileSharpenAmount`) that grow/shrink with tile size so 64 px tiles keep more detail and 16 px tiles stay crisp.
- **Cloudflare request** (`requestCloudflareImage` / `buildCloudflareRequestBody`): endpoint `${CLOUDFLARE_BASE}/accounts/<id>/ai/run/<model>`, header `Authorization: Bearer`, body `{prompt, width:1024, height:1024, num_steps:20}`. ⚠️ Workers AI returns the **PNG as raw binary** (not base64/JSON) — `runCloudflareAttempt` reads `res.blob()`, decodes via `URL.createObjectURL` and revokes it after. **Needs TWO env vars**: `VITE_CLOUDFLARE_API_TOKEN` (the bearer key, via `resolveApiKey`) **and** `VITE_CLOUDFLARE_ACCOUNT_ID` (read directly in `runCloudflareAttempt`, since it goes in the URL path, not a header).
- **Recraft request** (`requestRecraftImage` / `buildRecraftRequestBody`): OpenAI-compatible endpoint `${RECRAFT_BASE}/v1/images/generations`, header `Authorization: Bearer`, body `{model:'recraftv3', prompt, n:1, size:'1024x1024', style:'realistic_image', response_format:'b64_json'}`. `b64_json` returns `data[0].b64_json` (no CDN/CORS), decoded like the OpenAI path.
- **FLUX/SDXL/Recraft share the diffusion prompt path** (`CAPTION_PROVIDERS = {fal, cloudflare, recraft}`): they ignore instruction-style prompts and **invert negations**. The caption now asks straight for **flat 2D pixel-art top-down terrain (fantasy RPG game art) + "flat shading"** — an earlier "realistic material texture" caption made SDXL return photoreal 3D rock (relief + cast shadows) that turns to mush when downscaled. Strong **"fills the whole square evenly / repeats past all four edges"** anchors keep the model from drawing a single centered sprite (which would break autotiling); `generateBaseTileWithAI` still center-crops their output (adaptive `pickFalCropFraction`) before downscaling. Gemini/OpenAI keep their own instruction-style prompt and no crop.
- **Keys come from `.env.local` only** — `resolveApiKey(provider)` reads `VITE_OPENAI_API_KEY` / `VITE_FAL_API_KEY` / `VITE_CLOUDFLARE_API_TOKEN` / `VITE_RECRAFT_API_KEY` / `VITE_GEMINI_API_KEY` (+ `VITE_CLOUDFLARE_ACCOUNT_ID` read separately). **There is no key field in the UI** (removed for safety). ⚠️ The file must be named exactly `.env.local`; `VITE_*` is bundled into the client (not secret in a deployed build).
- In dev, requests go through **Vite proxies** ([vite.config.js](vite.config.js)): `/gemini` → `generativelanguage.googleapis.com`, `/openai` → `api.openai.com`, `/fal` → `fal.run`, `/cloudflare` → `api.cloudflare.com`, `/recraft` → `external.api.recraft.com`. The client picks `/gemini/v1beta`, `/openai/v1`, `/fal`, `/cloudflare/client/v4` or `/recraft` when `import.meta.env.DEV`.
- Gemini's default model gets a same-provider fallback (`FALLBACK_IMAGE_MODEL`); OpenAI and fal models don't fall back.
- `AITilePanel` is a **generator card** with a prompt box, preset chips, a model selector (Gemini + OpenAI options), and a **Generate Tileset** CTA — no key field.

### AI scenery props
[src/core/aiAsset.js](src/core/aiAsset.js) + [AssetAIPanel.jsx](src/components/Assets/AssetAIPanel.jsx) generate a **transparent, multi-cell prop** instead of an opaque tile. Shares the same `generateImage` dispatcher, models, proxies, and env-only key resolution as `aiTile.js`.

- The prop is generated on a solid magenta background and **chroma-keyed out locally** (`chromaKey` + `deFringeMagenta`, which kills the magenta edge halo from anti-aliasing) — works the same across both providers.
- After downscaling, `posterize` quantizes RGB so the AI's soft gradient shading reads as crisp flat pixel art; the asset prompt (`STYLE_BASE`) also demands flat colors / hard edges / no anti-aliasing.
- **Alpha is left CONTINUOUS by the pipeline** (no auto-binarize). Edge cleanup is user-controlled via the **Edge solidity** slider in the Assets view: `useAssetEditor.applySolidify(threshold, commit)` binarizes alpha using `solidifyAlpha` (canvasUtils) — `≥ threshold → 255`, below `→ 0`. It re-derives from a stored **raw** buffer (`rawRef`, set by `loadPixels`, invalidated on manual drawing) so the slider drags both ways; `commit:false` previews, `commit:true` records history. `AssetsView` auto-applies a default solidity (128) right after a generation so the result looks clean immediately.
- Target size is non-square: `pxW = cols*tileSize`, `pxH = rows*tileSize` (cols/rows 1..4).
- `AssetsView` now mirrors the tileset sidebar structure with the same **Tileset / Assets** top switch, card layout, and a primary **Generate Asset** CTA.

### AI procedural tilesets
In procedural mode the sidebar has an `AIProceduralPanel` (separate from the instant palette `Generate procedural`). It asks for a **single terrain prompt**, includes ready-made material presets, calls `generateBaseTileWithAI` once (one opaque square texture at tileSize), and hands it to `useTilesheet.generateFromTextures` → `generateTilesFromTextures` with `edge = null`, which composes the 48 autotiles (center fill + **borders synthesized from the texture itself** — darkened edges, no second prompt needed). This guarantees the tiles autotile since they're composed by bitmask rather than cropped from an AI image. (`buildTilePrompt`/`generateTilesFromTextures` still support a distinct `role:'edge'` texture, but the panel no longer exposes a second prompt — one image becomes a full set with edges and all.)

The panel also supports **importing your own texture** instead of generating. Pixel-art import defaults to the vendored MIT-licensed [Sprite Fusion Pixel Snapper](https://github.com/Hugo-Dz/spritefusion-pixel-snapper) WASM build: `pixelSnapper.snapImageFile` detects (or accepts an override for) the fake AI pixel size, snaps it to a real grid, and quantizes it to the chosen palette size entirely in-browser. Its decoded PNG then flows through `aiTile.processImageToTile` → the shared `onGenerated` → `generateFromTextures` path, so the snapped image becomes the center texture for all 48 autotiles. The old app-only pixelizer remains available by disabling Pixel Snapper, and Smooth mode bypasses it automatically. The preview/download shows the **snapped PNG** when Pixel Snapper ran, or the source image otherwise. The checked-in generated package lives in [src/vendor/spritefusion-pixel-snapper/](src/vendor/spritefusion-pixel-snapper/) with its license and pinned upstream commit, so normal builds do not need Rust or network access. `AITilePanel` still shows the raw AI preview for its single tile.

### Smooth (non-pixel) tilesets
A **"Smooth (cartoon/anime)"** toggle on the import path (`AIProceduralPanel`) makes a tileset **non-pixel-art**: `processImageToTile`/`postprocessTilePixels` take a `smooth` flag that **skips the palette quantize/posterize** (keeps full colour + gradients, only a gentle sharpen + seam repair), and `generateTilesFromTextures(…, smooth)` paints a **soft gradient border** (`paintEdgeGradient`/`paintInnerCornerSmooth`, darkening that fades back into the material) instead of the hard 3-tone bevel. The flag rides in the **`textures` definition as `smooth: true`** and is threaded everywhere the tileset descriptor flows (`{tiles,tileSize,frames,smooth}`: `editorTileset`/`editorSourceDef`/`aiTextures`, the `layerTiles` memo). **Rendering**: smooth tilesets render un-pixelated — editor `SheetCanvas` + `BiomeCardPreview` set `ctx.imageSmoothingEnabled = smooth` (+ canvas `image-rendering`), and `LevelCanvas` sets `app.canvas.style.imageRendering = smooth ? 'auto' : 'pixelated'` (pixi draws 1:1; the on-screen zoom is CSS scaling of the canvas, so image-rendering is the real control). For crisp detail, smooth tilesets pair with the new **128/256 px** tile sizes (added to both GRID selectors; `zoomConfig.MAX_CELL_PX` raised to 256). A guard warns (`showLevelNotice`) when `width/height × tileSize` exceeds ~16384 px (canvas/WebGL limit).

## Persistence (Supabase)

Assets (props), saved tilesets, and levels persist in **Supabase Postgres**, **per user** (SaaS model): the app is gated behind **Supabase Auth** (email + password) and every row carries a `user_id` scoped by RLS to `auth.uid()` — each account only sees its own data; the anon role has no table access. There is no localStorage (except supabase-js's own session persistence).

- **Auth**: [src/hooks/useAuth.js](src/hooks/useAuth.js) (session state + signIn/signUp/signOut/resetPassword/updatePassword, `onAuthStateChange` incl. the `PASSWORD_RECOVERY` event) + [src/components/Auth/AuthGate.jsx](src/components/Auth/AuthGate.jsx) (pixel-themed sign-in / create-account / reset-password screens; wraps `<App/>` in `main.jsx` via a render prop and **keys App by `user.id`** so switching accounts remounts the app and the gallery hooks reload the new user's tables). The topbar shows the signed-in email + a Sign out button (`account-group` in App.jsx). **When Supabase isn't configured** (`supabaseReady` false) the gate is transparent: the app runs unauthenticated in local mode, galleries empty — the dev workflow without env vars still works. Sign-up may require email confirmation depending on the Supabase project's auth settings (the UI handles both). `20260717000000_user_accounts.sql` adds `user_id uuid default auth.uid()` + owner-only policies; legacy rows (`user_id` null) are invisible until claimed with a manual UPDATE (see the migration's header comment). Inserts don't pass `user_id` — the column default `auth.uid()` fills it from the request JWT.

- **Client**: `@supabase/supabase-js` via `src/lib/supabase.js`'s **lazy `getSupabase()`** (dynamic import on first use → own chunk, not in the initial bundle; a browser can't use the raw Postgres connection string — only the REST API). Needs `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` in `.env.local` (anon key is public/safe; RLS is the gate).
- **Schema**: `supabase/migrations/` (apply **all** files in order) — `assets` (props, base64 pixels), `tilesets` (a `definition` jsonb that *regenerates* the 48 tiles, not the rendered pixels: `{mode:'procedural',biomeId,colors}`, `{mode:'textures',centerPixels,edgePixels,colors}` or `{mode:'draw',basePixels}`; optional `overrides: {idx: base64}` for hand-edited tiles and `animationFrames: N` on procedural defs), `levels` (a **`layers` jsonb** array of `{id, name, kind, visible, tileset, gridB64, manualTilesB64}` + `placed_props` jsonb + `seamless_edges`; manual tile indices are stored +1 so they fit in unsigned bytes). The old single-layer columns (`grid`, `manual_tiles`, `tileset`) are legacy: still read by `handleLoadLevel` for old rows, no longer written (`*_level_layers.sql` adds `layers` and drops the NOT NULL on `grid`). All three tables carry `user_id uuid default auth.uid()` (`*_user_accounts.sql`) with owner-only RLS policies (`to authenticated`, `user_id = auth.uid()`). Apply via `psql "<conn string>" -f <file>`, Dashboard SQL editor, or git↔Supabase sync.
- **Data layer**: `src/lib/db.js` (thin async CRUD per table) + `src/lib/serialize.js` (`bytesToBase64`/`base64ToBytes`). `saveLevel` writes the `layers` jsonb; `listLevels` returns whole rows so `handleLoadLevel` can restore both the layered and the legacy format.
- **Loading a tileset/level** reuses the existing generators: `App.jsx#applyTilesetDefinition` calls `generateFromBitmap` (draw) or `generateFromBiome` (procedural) — definitions are tiny, tiles are regenerated on demand.
- **UI**: the bottom **GalleryDock** (Tilesets tab) saves the current tileset and lists saved ones (`SavedTilesetCard` regenerates each preview); its Props tab lists saved assets. `LevelStorage` (level sidebar) saves/loads levels. The Assets view also has its own `AssetGallery`.

### ⚠️ Secrets
Never commit API keys, the DB password, or hardcode them in source. AI keys belong **only in `.env.local`** (git-ignored) — `VITE_OPENAI_API_KEY` / `VITE_GEMINI_API_KEY` / `VITE_FAL_API_KEY` / `VITE_CLOUDFLARE_API_TOKEN` (+ `VITE_CLOUDFLARE_ACCOUNT_ID`) / `VITE_RECRAFT_API_KEY`. There is no in-app key field anymore. The Supabase **anon key** is the exception — public by design, safe to ship. Note `VITE_*` vars are embedded in the client bundle, so even env keys ship to the browser in a deployed build; for true secrecy proxy the calls through a backend. If a secret is pasted into a non-ignored file or shared in chat, treat it as compromised: rotate OpenAI keys at platform.openai.com, Gemini keys at aistudio.google.com/apikey, the DB password in the Supabase dashboard.
